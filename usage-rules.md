# Ccusage Usage Rules

This file is the prescriptive DO / NEVER contract for working in Ccusage. Everything else an agent needs, the Intent tooling, the rule library, the critics, the hooks and the gate, is in `AGENTS.md`, which `intent agents sync` keeps current; this file is seeded once and never overwritten, so it carries only what the project owns.

This is Ccusage's own hand-authored contract, not the `usage_rules` Hex library's per-dependency `deps/<pkg>/usage-rules.md` files, which share the filename and are generated by that tool.

## Project conventions

- Before a commit, run `bin/devbin check all`, `bin/devbin test all` and `bin/devbin build`. `bin/.devbin/config.yaml` is the one home of those checks, and every cargo command in it takes `--locked`.
- When release tooling, packaging or CI changes, also run the two checks `docs/releasing.md` lists that devbin does not hold: the signing tests and actionlint.
- AGENTS.md's Bats prerequisite, `bats -r tests/`, and unlocked `cargo test` and `cargo build` are Intent's generic language text, not this project's commands; Intent issue 0672 records that gap in AGENTS.md's template. Ccusage has no Bats tests; its checks are the `bin/devbin` commands above.

## NEVER DO

- Never edit `AGENTS.md` directly; `intent agents sync` regenerates it.
- Never edit the hook stanzas in `.claude/settings.json`; re-apply them with `intent claude upgrade --apply`.
- Never bypass the pre-commit hook with `--no-verify` on shared branches without a justification in the commit message. Find the hook git actually runs with `git rev-parse --git-path hooks`: it is `.git/hooks` by default, and elsewhere when `core.hooksPath` is set.
- Never create steel thread or work package directories by hand; use `intent st new` and `intent wp new`.
- Never edit `status:` fields in a thread's frontmatter; use the `intent st` and `intent wp` lifecycle verbs.
- Never wrap lines in markdown files by hand.
- Never edit devbin's vendored runtime: `bin/devbin`, `bin/.devbin/lib/` and `bin/.devbin/manifest.sha256`. `bin/devbin upgrade` replaces it, and `bin/devbin doctor` checks it against the manifest. The project's own devbin files are `bin/.devbin/config.yaml` and any handler in `bin/.devbin/cmd/`.
