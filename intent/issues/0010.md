## Context

vc's two reads of cc's ISSUE:0008 units on 2026-11-17 passed both to land in 0.1.10. These six findings were left for a later release, since hv wants one cut and no small releases (decision 2). None blocks a switch or loses a login.

## Items

1. `src/usage.rs`, about lines 840 to 843: a renewed login that turns out to be another account's gets the generic "could not verify the renewed login matches this profile", with no remedy. It predates ISSUE:0008 and needs a narrow race.
2. `sessions::pinned_to` compares paths as written, so a session pinned through a symlink or a relative path is not seen by doctor or by the refusal. A pin normally comes from `ccusage dir`, which prints an absolute path.
3. `switch::admitted` calls `usage::verified_token`, so an incoming profile with an email and an expiring token is renewed in its own store before the check refuses it as Foreign: refused before any move, but not before every write. The outgoing check behaves the same way.
4. A seated profile with no email and no account record is always refused, and the Foreign message says "run ccusage login NAME", which repeats the refusal. It should point to setting the profile's email.
5. `sessions_note` in `src/cli.rs` and `pinned_now` in `src/display.rs` drop a `shared_dir()` error (`if let Ok`, `.ok()`), so a config error makes the pinned note disappear without a word, though the verb's main path reports the error (No Silent Errors).
6. `relocate`'s retry on Foreign verifies both logins again, so a foreign incoming login costs two profile calls before its refusal. Cost only.

## Acceptance

- Each item is fixed, with a test where it changes behaviour, or ruled out with its reason in this record.
