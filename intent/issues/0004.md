## Symptom

The repo ships Python, against the house rule (no `.py` file, and no Python script, hook or one-liner that a repo commits or installs):

- `tools/sign-macos` (112 lines) and `tools/finalize-release` (96 lines) are `#!/usr/bin/env python3` scripts.
- `tests/signing_test.py` (128 lines) runs in CI on all four targets and in `tools/release`'s validation.
- Python heredocs sit in `tools/formula:43` and `tests/release.sh:102`.
- `tools/release:47` requires `python3`, `docs/releasing.md` lists Python 3 as a maintainer tool, and `.gitignore` carries `__pycache__/`.

The shipped binary and the Homebrew package contain no Python. This is the repo and the release path.

## What the Python does

- `sign-macos` unpacks the two Mac archives, rejecting path traversal and symlinks. It checks each architecture with `lipo` and signs with the Developer ID (identifier, hardened runtime, secure timestamp). It verifies the designated requirement and the timestamp, optionally notarises, repacks, and writes `MACOS-SIGNING.json` binding the archives to their checksums and signing identity.
- `finalize-release` validates `SHA256SUMS` and the manifest, runs `sign-macos`, uploads, downloads again to verify what landed, then publishes the draft.
- The heredocs render the Homebrew formula from the signing manifest and build fixture assets for the release tests.

## Options

1. Rust `xtask` (vc recommends): a workspace member that never ships (`cargo xtask sign-macos`, `finalize-release`, `formula`). The checks become typed code, and their tests become cargo tests on the existing four-target CI matrix with nothing extra to install. `serde_json` and `sha2` are already dependencies; archive handling adds the `tar` and `flate2` crates, to the `xtask` only. It is the larger change: a workspace, and something like 400 to 600 lines of Rust.
2. zsh: the house rule's other choice. macOS already has every tool it needs (`codesign`, `lipo`, `shasum`, `tar`, `/usr/bin/jq` 1.7.1). Tests move to stub-on-PATH shell tests like `tests/release.sh`. It is smaller, but shellcheck cannot lint zsh, the Linux runners need zsh installed to run the tests, and archive-entry validation and JSON assembly in shell are the fiddliest part of the most security-critical step.
3. Rejected: signing in CI, which would export the Developer ID key the release design keeps in hv's Keychain; and Swift scripts, which are outside the house languages.

## Acceptance

- No `.py` file, Python shebang, `python3` invocation or Python heredoc remains in the repo, its CI or its docs, and `.gitignore` drops `__pycache__/`.
- Every check the Python enforced has a test that fails when that check is removed.
- devbin's release dry run passes for 0.1.6, and the 0.1.6 release runs end to end on devbin's `release` and `formula` commands.
- `tools/test-keychain-upgrade` and `tests/keychain-upgrade.swift` are gone, and no doc, check or CI step names them.
- No bespoke release tool or script remains: `tools/` and the `xtask` are gone, the release and the formula run through `bin/devbin`, and any step of Ccusage's own is a handler in `bin/.devbin/cmd/`. `bin/.devbin/config.yaml` holds the release's gates, actionlint among them.
- `bin/devbin doctor` has no version note, or this issue records why it stays.
