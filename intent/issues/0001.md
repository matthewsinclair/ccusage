## Symptom

`ccusage` with no command prints the help text. Checking the active account takes `ccusage usage`, and checking every account takes `ccusage usage --all`.

## Wanted

- `ccusage` shows usage for the active account, exactly as `ccusage usage` does now.
- `ccusage --all` shows every configured account, exactly as `ccusage usage --all` does now.
- Help comes from `ccusage help` and `ccusage --help` only.

## Cause

`src/cli.rs:100` prints HELP when no command follows the global flags, and the global flag loop at `src/cli.rs:72` rejects `--all` as an unknown option.

## Fix outline

- With no command, dispatch to `usage`.
- Let the usage flags (`--all`, `--json`, `--refresh`) end the global flag loop and fall through to `usage` when they come first, so `ccusage --all --json` composes.
- Keep `--config`, `--no-color` and `--verbose` global. `ccusage --verbose` becomes verbose usage for the active account.
- First run with no config: keep the actionable `no config at ...; run ccusage init` error, add a pointer to `ccusage help`, exit nonzero.
- Update HELP (the `Usage:` line, plus a line for the bare form), README (Usage and dashboard), and the CLI tests.

## Acceptance

- Against the same fixture state, `ccusage --json` and `ccusage usage --json` emit the same report and exit status; likewise `ccusage --all --json` and `ccusage usage --all --json`.
- `ccusage help` and `ccusage --help` print the help and exit 0. Bare `ccusage` never prints it.
- Bare `ccusage` with no config exits nonzero with the init hint and the pointer to `ccusage help`.
- Unknown commands and unknown options fail exactly as before.
- `cargo fmt --check`, `cargo clippy --all-targets --locked -- -D warnings` and `cargo test --locked` pass.
