## Background

0.1.9's archives and installed trees hold `bin/ccusage` alone (802de63, under ISSUE:0007). After a formula's install, Homebrew's build.rb moves metafiles (a LICENSE, a README and the like) from the buildpath to the keg's root, and when none land there, as for a keg whose install moved the whole archive into `libexec`, it moves them out of `libexec` instead. The keg's manifest then named a LICENSE the keg did not hold, and `bin/devbin doctor` failed the keg.

devbin 0.1.24 fixed that in its install body (devbin issue 0349): the install copies the archive into `libexec`, so Homebrew finds the archive's own metafiles in the buildpath, puts them at the keg's root, and leaves `libexec` alone. Ccusage's formula takes that body at `@@INSTALL@@` (`packaging/homebrew/ccusage.rb`), so the next render carries the fix with no change to the template. On Linux the formula runs `bin/devbin install` in the tag's checkout, whose root holds the LICENSE Homebrew moves, so `libexec` keeps its own there too.
