# WP-03: Shared mode on one live login: use, run, dir, login, logout and adoption

## Objective

Every verb follows the one live login. `use` and `run` move logins through WP02, usage fetches and `list` read each account's login from where it lives, `login` and `logout` keep the layout whole, `dir` stops naming a directory for the active account, and the first `use` after the upgrade adopts today's layout.

- **Builder:** cc, and ic signs the verbs' text. **Depends on:** WP02.
- **One `use` function:** the CLI's `use`, `run NAME`, the TUI's `a` key and `which --use` all call it. It moves the login (WP02), writes the account record, selects the profile, and on macOS unsets launchd's `CLAUDE_SECURESTORAGE_CONFIG_DIR`. Today the `a` key writes `active.json` alone and skips shared mode's switch, and that copy goes. Whichever of this work package and ST0002/WP03 lands first makes the function, and the other calls it.
- **One place says where a login lives:** the shared store when its profile is active, the profile's own otherwise. Usage fetches, renewals, `list` and `doctor` all ask it. The usage cache stays bound to the directory and the credential it was read from, so a switch costs each of the two accounts one fetch.
- **`ccusage run`:** launches Claude with `CLAUDE_CONFIG_DIR` at the shared config and with `CLAUDE_SECURESTORAGE_CONFIG_DIR` removed from the child's environment, so a stale shell cannot hand it a profile's directory. `run NAME` switches first when NAME is not active, as it does today.
- **`ccusage dir`:** with no name, or with the active profile's, it prints nothing and fails with a line saying sessions read the shared config's login. Molt, and any launcher built on the README's line, then drop the variable. `dir NAME` for a parked profile prints its directory as now.
- **`login` and `logout`:** `login NAME` for the active profile seats the fresh login and drops the one it replaces. `logout NAME` refuses the active profile and says to switch first.
- **Adoption:** on today's layout, where every profile still holds its own login, the first `use NAME` seats NAME's parked login over the shared config's own one and says whose it replaced. It does so only when that login's account has another login parked in a profile, or when that login can no longer be renewed. Otherwise it refuses and says how to park that account first.
- **Parking everything:** one way, whose spelling is ic's, to put the active login back in its profile and leave the shared store without one. It is how shared mode is turned off and how hv goes back to an older ccusage, which reads logins from the profiles.
- **Shared mode off:** nothing changes, and every existing test passes unchanged.
- **What `use` says:** that running sessions follow at their next request, and what stays the old account's until a session restarts.
- **Tests:** in the `Sandbox`, on file stores, for each verb and for adoption.
- **Done when:** AC-03.1 to AC-03.4 are green.
