# WP-04: Doctor for the one live login

## Objective

`ccusage doctor` says where each account's login is, and flags everything that would make a switch go wrong before hv relies on one.

- **Builder:** cc. **Depends on:** WP02, beside WP03.
- **Where the logins are:** for the shared store and each profile's, whether it holds a login. It fails when an account has none or two, and when a move's journal is still there.
- **Whose the shared login is:** verified as the active profile's when the endpoint can be reached. When it cannot, doctor says the check was not made, never that it passed.
- **Sessions that will not follow:** running `claude` processes whose launch environment names a login directory other than the shared config's, or a `CLAUDE_CONFIG_DIR` other than the shared config, each with its pid, start time and working directory. It reads the process itself (`ps -E` on macOS, `/proc/<pid>/environ` on Linux) and looks only for those two variables. Where neither works it says the check was skipped.
- **Claude Code's flags:** from the shared config's flag cache, a line when the session-owner prompt (`tengu_bubbly_fountain`) is on or the sibling-login watch (`tengu_streamed_thimble`) is off, saying what a switch will then do.
- **The line limit:** the shared document's length against the `security -i` limit, as a length and nothing else.
- **What goes:** today's shared-mode warnings that no longer hold, that the shared config "still holds a login of its own" and that `CLAUDE_SECURESTORAGE_CONFIG_DIR` names another profile.
- **Tests:** in the `Sandbox`, with the process listing supplied by a stand-in as `launchctl` is today.
- **Done when:** AC-04.1 and AC-04.2 are green.
