# WP-02: The which rule: earliest reset first, with the cap from config

## Objective

One pure function takes the accounts' reports, the time now, the cap and an optional model name, and returns the chosen account, the ranked rest and a reason for each. It is the only implementation of the rule: the `which` verb, the TUI marker and `predict`'s simulation all call it.

- **Builder:** cc (proposed). **Depends on:** WP01.
- **Where it lives:** its own module, pure: no clock, no file, no network. The time now, the cap and the cache's lifetime are arguments, and the lifetime is `usage`'s own constant, not a second number.
- **Usable:** an account whose report holds a snapshot fetched within the cache's lifetime, with a `weekly_all` window whose reset is still ahead. Anything else is unknown: listed with its reason (the report's error, stale data, a reset that has passed, or no weekly window) and never chosen. A reset that has passed means the cached percent belongs to the previous window. A fresh snapshot is usable even when its report carries an error, as it does when only the cache save failed.
- **Eligible:** a usable account whose `weekly_all` is below the cap. With a model, that model's `weekly_scoped` window must be below the cap too. An account with no scoped window for the model is bounded by `weekly_all` alone.
- **Rank:** `weekly_all` reset ascending, each rounded to the nearest minute, so the endpoint's jitter cannot decide and one reset cannot fall in two minutes; then most headroom; then name, so the order is stable. A `weekly_all` with no reset ranks after every dated one, and its reason says so.
- **Nothing eligible:** the result says so and names the soonest reset among the known accounts.
- **Cap:** a new optional key in `config.toml` (proposed: a `[which]` table with `cap = 95`). Its default is defined once, and a value outside (0, 100] is refused. A config that does not set the key is written back without it, by `add` and `init` alike, because `Config` denies unknown fields and every older binary refuses a config that carries it. Tests take the cap from the config they write or from that default, never from a literal.
- **Tests:** the worked example as a fixture test with now at 2026-11-13T05:27Z and the caches' own reset times, jitter included. It must choose hello and rank engineering04, then engineering01 and engineering02, then engineering00. Also each cause of unknown, a reset a fraction of a second before the hour tying with one a fraction after, the headroom tie-break, a missing reset, nothing eligible, and the model filter.
- **Done when:** the rule is one pure function, and AC-02.1 to AC-02.4 are green.
